## Task 03-01-T1 — Server actions

**Satisfies**: REQ-015 (server half)
**Agent**: `coder-sr`
**Depends on**: 01-01-T1 — provides the `client_job_pricing` table and its `database.ts` entry.

### Files owned (exclusive)

```
src/lib/actions/client-job-pricing.ts    (new)
```

### What to do

Copy the structure of the location actions in `src/lib/actions/clients.ts:297-540` exactly:
`'use server'`, a file-local `requireAdminRole()` (yes, re-implemented — that is the convention,
`CODEBASE-MAP.md §1`), a hand-rolled `parseClientJobPricingFormData(formData)`, writes through
`createAdminClient()`, then `revalidatePath`.

Parsing:
- `job_id` non-empty → else `fieldErrors.job_id = 'Job is required.'`
- `hourly_rate_cents` via `parseDollarsToCents` from `@/lib/pricing/money`; `null` →
  `fieldErrors.hourly_rate_cents = 'Enter a valid hourly rate in dollars.'` (empty, non-numeric and
  negative all land here — `parseDollarsToCents` returns `null` for all three)
- `effective_from` must match `/^\d{4}-\d{2}-\d{2}$/` — reuse the local `isValidDate` idiom from
  `clients.ts` / `appointments.ts:68-70` rather than importing one
- `notes` optional, trimmed, empty → `null`

There is no mode to read and no column routing to do: the parsed amount goes straight into
`hourly_rate_cents`.

Writes:
- `createClientJobPricing(clientId, ...)` inserts
  `{ client_id, job_id, hourly_rate_cents, effective_from, notes }`, selects `id`.
- `updateClientJobPricing(pricingId, ...)` updates the same set,
  `.eq('id', pricingId).eq('is_archived', false).select('id, client_id').maybeSingle()`, returning
  `'Pricing rule not found.'` on no row — same idiom as `updateLocation`.
- `archive` / `restore` flip `is_archived`, same as `archiveLocation` / `restoreLocation`. They
  receive no `clientId`, so read the row's `client_id` back from the update's `.select()` to build
  the revalidation paths.
- On a unique-constraint failure from
  `client_job_pricing_client_id_job_id_effective_from_key`, return
  `fieldErrors.effective_from = 'A rate for this job already starts on that date.'` rather than the
  raw Postgres message. `invoices.ts:202-205` has the existing `isUniqueConstraintError` idiom —
  copy it, do not import it.

Revalidation on every mutating action: `revalidatePath('/solutions/clients')`,
`revalidatePath('/solutions/clients/${clientId}')`,
`revalidatePath('/solutions/clients/${clientId}/pricing')`. Because a rule change moves prices on
every un-invoiced appointment for that client, also
`revalidatePath('/solutions/appointments')`. `create` and `update` additionally
`redirect('/solutions/clients/${clientId}/pricing')`, matching how `addLocation` redirects;
`archive`/`restore` do not redirect.

Read `node_modules/next/dist/docs/01-app/01-getting-started/07-mutating-data.md` and
`node_modules/next/dist/docs/01-app/03-api-reference/04-functions/revalidatePath.md` first.

### Acceptance criteria

- Creating a rule with rate `38` effective today persists `hourly_rate_cents = 3800`.
- A second rule for the same client+job with the same `effective_from` returns
  `fieldErrors.effective_from` and writes nothing — not a 500, not an unhandled rejection.
- The same client+job with a different `effective_from` succeeds.
- Rate empty, non-numeric, or negative → `fieldErrors.hourly_rate_cents`, nothing written. `0` is
  accepted (DET-5).
- `effective_from` malformed → `fieldErrors.effective_from`, nothing written.
- Archiving a rule sets `is_archived = true` and the row stops being returned by `pickEffectiveRule`
  (verify through `fetchClientJobRules`, which filters `is_archived` in the query).
- Called without an admin session, every exported function returns
  `{ success: false, error: 'Unauthorized' }` and writes nothing.
- `npm run lint` clean; this file contributes no `npx tsc --noEmit` error.

### Out of scope

- Do not edit `src/lib/actions/clients.ts`, or any component or route — T2 and T3 own those.
- Do not extract a shared `requireAdminRole` / `isValidDate` / `isUniqueConstraintError`

- Do not add zod or any validation library.
- Do not add a `pricing_mode`, a `flat_price_cents`, an `effective_to`, percentage discounts, or

### What to do

**`client-job-pricing-form.tsx`** — model on `src/components/admin/location-form.tsx`:
`'use client'`, `useActionState`, a `SubmitButton` using `useFormStatus`, the same
`h-11 rounded-xl border-neutral-200 bg-white px-3.5 text-sm shadow-sm` inputs, the same
`text-xs text-red-600` field errors, the same emerald submit button.

- `job_id`: a `<select>` over `props.jobs`, each option showing the job's standard rate as a hint
  (`Hourly Deep Clean — standard $60.00/h`) so the admin can see what they are overriding. Use
  `formatRate` from `@/lib/pricing/money`.
- `hourly_rate_cents`: one `type="number" min="0" step="0.01"` input,
  label `Rate ($/hour)`, helper `Charged per scheduled hour for this client's appointments on this
  job.` Default value from `pricing?.hourly_rate_cents` as `(cents / 100).toFixed(2)`.
- `effective_from`: `type="date"`, defaulting to `pricing?.effective_from` or today's date. Helper:
  `Applies to appointments scheduled on or after this date. Earlier appointments keep the previous rate.`
- `notes`: `Textarea`, optional, placeholder `e.g. Loyalty rate agreed Sept 2026`.
- Bind the action:
  `pricing ? updateClientJobPricing.bind(null, pricing.id) : createClientJobPricing.bind(null, clientId)`.

There is no mode select. One rate field is the whole form.

**`client-job-pricing-list.tsx`** — model on the `LocationCard` block in
`src/app/(internal)/solutions/(admin)/clients/[id]/page.tsx:23-80` and on
`src/components/admin/jobs-list.tsx`.

- Group rows by `job_name`, jobs alphabetical, rows within a job by `effective_from` **descending**.
- Within each job group: the newest non-archived row with `effective_from <= today` gets an emerald
  `Current` chip; rows with `effective_from > today` get a neutral `Scheduled` chip; older
  non-archived rows get `Superseded`; archived rows get `Archived` and render muted. Compute this
  from `rows` and `today` inline — **do not import `src/lib/pricing/resolve.ts`** into a Client
  Component (REQ-004's acceptance greps for exactly that). It is a three-line date comparison and it
  is a display concern.
- Each row shows `formatRate(row.hourly_rate_cents)`, the effective date, the notes, an `Edit` link
  to `/solutions/clients/${clientId}/pricing/${row.id}/edit`, and an Archive/Restore button wired
  through `archiveClientJobPricing` / `restoreClientJobPricing` in the same
  form-action-with-hidden-input style `LocationCard` uses.
- Empty state: a card reading
  `No custom pricing for this client — appointments bill each job's standard hourly rate.`
- Archived rows are hidden behind a toggle, matching how `jobs-list.tsx` handles archived jobs.

Both files: responsive down to 400px, no new dependency, no new primitive.

- `grep -n "@/lib/pricing/resolve\|@/lib/pricing/lookup\|pricing_mode\|flat_price_cents"` on both

## Verification (for `verifier`)

### Changed-risk surface

A new admin-only surface over a table with a unique constraint, whose rows silently move the price
of every un-invoiced appointment for that client. The failure modes worth hunting: the unique
violation surfacing as a raw Postgres message instead of a field error; an `effective_from` off by
one day from a timezone-naive date string; and a `Current` chip that disagrees with what the
resolver actually picks.

### Commands

```bash
npm run lint
npx tsc --noEmit     # clean, independent of Phase 2 (corrected 2026-09-18, REQ-017 — the rename
                     # produces no type error at all). Any error here is a defect.
npm test             # read the `pass` / `fail` summary, not the exit code
supabase db reset && npm run seed:admin && npx supabase db query --file supabase/test-data.sql --local
# prove the seed by row count before trusting the smoke script (B-07):
npx supabase db query --local <<'SQL'
  SELECT count(*) AS jobs FROM public.jobs WHERE hourly_rate_cents > 0;
  SELECT count(*) AS clients FROM public.clients;
  SELECT count(*) AS rules FROM public.client_job_pricing;
SQL
```

These routes are new, so REQ-021's ten-route walk does not cover them — but the same failure mode
applies to any `.select(...)` they write. Run the smoke script with the devtools network panel open
and record **zero `/rest/v1/` responses ≥ 400**.

### Smoke script

Signed in as the seeded admin, against a reset + seeded local stack.

1. Client detail page → `Custom Pricing` → the list shows the seeded `$38.00/h` loyalty rule on
   `Hourly Deep Clean`, marked `Current`.
2. `Add Rate` → job `Hourly Deep Clean`, rate `35`, effective the **1st of next month** → save. The
   list now shows two rules for that job: today's `Current`, next month's `Scheduled`.
3. `Add Rate` again, same job, same next-month date → the form re-renders with
   `A rate for this job already starts on that date.` under the date field, and
   `SELECT count(*) FROM client_job_pricing` is unchanged.
4. `Add Rate` with rate `0` → accepted (DET-5). With `-1` → field error, nothing written.
5. Edit a rule, clear the rate → field error, nothing written.
6. Archive a rule → it moves under the archived toggle, `is_archived = true`. Restore it → back, and
   it re-appears in the `Current`/`Superseded` ordering.
7. **End-to-end resolver check** (requires 02-02-T1): create an appointment for that client on the
   1st of next month with `Hourly Deep Clean`, 09:00–11:30 → its detail page prices at
   `$35.00/h × 2h 30m = $87.50`, labelled `Client rate`. If Phase 2 has not landed yet, verify with
   `SELECT * FROM client_job_pricing WHERE client_id = ... ORDER BY effective_from DESC` instead and
   note the deferral in the report.
8. Sign in as a seeded employee → `/solutions/clients/<id>/pricing` redirects to
   `/solutions/schedule`, and a direct PostgREST `select` on `client_job_pricing` returns zero rows
   (REQ-008 still holding).
9. Repeat step 2 at 400px viewport width — no horizontal scroll, all controls reachable.

REQ-015's acceptance criteria met in full, REQ-008 still holding (step 8), the `Current` chip
agreeing with `pickEffectiveRule` on an inclusive `effective_from === today` boundary, and
