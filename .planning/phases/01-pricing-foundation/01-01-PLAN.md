## Verification (for `verifier`)

### Changed-risk surface

A rename of a live NOT NULL column that eight unowned files read; a backfill of a junction table
whose UPDATE path has **never once executed** in this schema's history; a new denormalized money
column; and a deliberate, human-approved reinterpretation of every job's price. The three things to
hunt for:

1. **A compensating conversion that should not exist.** Any division by
   `estimated_duration_minutes`, any recalculation of `hourly_rate_cents`, any "helpful" correction
   of the reinterpretation. The human chose this; the migration must not soften it.
2. **A historical invoiced amount that moved.** The ARCH-1 carve-out covers *future* pricing only.
   `invoice_appointments.billed_amount_cents` must equal what the app charged before.
3. **A green signal over a broken reality.** This phase has now produced two of them, so treat it
   as the pattern it is, not a coincidence:
   - `npx tsc --noEmit` is **clean with the rename landed** — the clients are untyped, so the
     compiler never sees the column (REQ-017, D-22). A clean `tsc` is not evidence the rename is
     safe; it is evidence the compiler was never watching. The breakage is runtime `42703`/400s.
   - `npm run seed:admin` **exits 0 while writing nothing** (B-07). Accept no seed claim that is
     not a row count read back from the database afterwards.
   Anywhere in this phase's report that an exit code or a console line stands in for a row count or
   an HTTP status, the claim is unproven.
